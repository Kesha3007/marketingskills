# Сверка чатов и Supabase — 23 октября 2026

**Источник решений:** последние доступные сообщения чата «Создание ИИ помощника» и сверка с текущим планом Marketing Skills.  
**Проверено непосредственно:** структура и количество строк в Supabase `prazske_drevo` по read-only запросам.  
**Не проверено:** реальная работа CRM API и n8n, потому что к серверу и KeyCRM из этого чата доступа нет; пользователь просит пока не запускать тесты и не менять действующие workflow.

## Приоритет, согласованный в предыдущем чате

1. В n8n выделить отдельный раздел/папку **AI CRM Agent**.
2. Первым создать workflow **01 - CRM AI Agent**: Chat/Manual Trigger → AI Agent → OpenAI Chat Model → ограниченные read-only KeyCRM-инструменты.
3. Начать с **Get KeyCRM Client** (по ID), затем добавить карточки воронок, заказы, звонки и доступную историю. Список действий должен быть whitelist и ограничен нужным контекстом.
4. Только после того, как агент умеет выбирать инструменты и анализировать CRM, вернуться к автоматизированному переносу клиентской истории и памяти в Supabase.
5. В будущем агент готовит предложения создания/редактирования CRM, запись возможна **только после явного подтверждения уполномоченным пользователем и серверной проверки**.
6. Не менять существующие рабочие таблицы, Views, связи, KeyCRM → n8n → Supabase и рабочие n8n workflow.

Старые учебные JSON с анализом первых 50 заказов — **не основной проект**, не следует принимать их за финальную архитектуру.

## Что создавать дальше

**Первый технический шаг:** папка `AI CRM Agent` в n8n и workflow `01 - CRM AI Agent` с Chat Trigger, OpenAI Chat Model и `Get KeyCRM Client` как строго read-only инструментом. Рабочий сервер ещё не подключён к этому чату, поэтому импорт и аутентификация пока не производились.

Подход к CRM — live API запросы к KeyCRM, а не чтение из устаревающих копий в Supabase. Supabase остаётся будущей базой памяти, истории и предложений действий после основного подключения CRM.

## Границы

- Не запрашивать и не сохранять в публичном GitHub API-ключи, клиентские телефоны, адреса или переписки.
- Не утверждать, что агент уже работает в n8n.
- Не давать модели свободный HTTP-инструмент, способный менять любые записи CRM.
- Изменения в KeyCRM допускаются только после пользовательского подтверждения и отдельного исполнителя.
- Таблицы `public` и существующие n8n процессы оставлять без изменений.
