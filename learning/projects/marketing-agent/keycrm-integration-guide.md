# Подключаем KeyCRM к ИИ-агенту: безопасный старт

**Статус (2026-10-23):** подготовлены JSON-файлы, но доступ к твоему n8n/KeyCRM из чата не предоставлен; импорт, авторизация и API-проверка ещё не выполнялись.

## 1. Что добавлено

- [Ручной read-only workflow](workflow-keycrm-readonly-snapshot.json) — один тестовый GET и краткая агрегированная сводка.
- [Subworkflow-инструмент](workflow-keycrm-readonly-tool.json) — API-запрос, затем удаление персональных полей из ответа для агента.
- [Чат-агент v1](workflow-agent-keycrm-v1.json) — частный чат, OpenAI Chat Model и вызов subworkflow; после импорта необходимо выбрать subworkflow в ноде-инструменте.

Все шаблоны **inactive** и содержат **только GET**, никаких CRUD-изменений. Они требуют настройки под фактическую версию n8n и ответа KeyCRM. Никаких подтверждаемых операций записи пока не реализовано.

## 2. Настройка credentials

1. Проверь версию n8n и наличие резервной копии; используй имеющийся VPS, не трогая рабочие сценарии.
2. В KeyCRM создай/выбери ключ API с минимальным доступом, если интерфейс позволяет ограничить область. **Не публикуй API-ключ и не присылай в чат**.
3. В n8n создай credential **Header Auth**: имя заголовка `Authorization`, значение `Bearer <SECRET>`. Секрет вводится только в n8n.
4. Импортируй [ручной read-only workflow](workflow-keycrm-readonly-snapshot.json). В HTTP Request выбери именно этот credential.
5. Проверь `GET https://openapi.keycrm.app/v1/order?limit=50&page=1`. Если контракт API изменился, сначала сверяйся с актуальной документацией KeyCRM. Не изменяй живые данные для тестирования.
6. Проверь Output ноды **Aggregate without personal data**. Она выводит подсчёт заказов по ID статуса и источника; это **только страница 1**, не вся база, не период и не отчёт по выручке.
7. После этого импортируй subworkflow и чат-агент v1. В ноде `KeyCRM aggregate via subworkflow` выбери импортированный subworkflow (ссылка workflow ID пока пустая), а в модели OpenAI выбери свои credentials.
8. Запусти локальный тест в editor chat. Доступ к чату держи непубличным и за паролем n8n.

**Внимание:** n8n может хранить промежуточный полный API-ответ в execution history даже если конечная Code-нода его обезличила. На рабочем сервере отдельно настрой retention/redaction и доступ к execution data; не публикуй скриншоты или экспорты с персональными полями. Для production предпочтительнее извлекать уже агрегированные данные через серверный read-only слой, чтобы сырые PII вообще не попадали в workflow агента.

## 3. Что подтвердим после первого запуска

- Валидность текущих эндпоинтов, полей и пагинации KeyCRM для **твоего** аккаунта.
- Реальная семантика ID статусов, источников и денежных полей.
- Доступность комментариев менеджера и полной истории переписок именно через API.
- Какие действия записи доступны API и какие ограничения на них можно поставить.

## 4. План записи с обязательным подтверждением

1. **Сначала read-only** и журнал результатов.
2. Создание или изменение заказа/карточки/контакта — как **proposal**, без выполнения: целевой ID, что изменится, кто запросил, причины, до/после.
3. Отдельный шаг **approval** через доступный только уполномоченным сотрудникам канал, с одноразовым подтверждением, временем жизни и проверкой ролей.
4. Независимый исполнитель с отдельными правами, ограниченными типами операций и серверной проверкой параметров. Approval сам по себе не делает операции безопасными.
5. Запись audit log (инициатор, approved_by, old/new, время, статус), проверка результата, сценарий отказа и отката.

Не давать агенту свободную ноду HTTP Request с общим CRM API key, способную делать любые методы: только строго определённые инструменты.

## 5. «Учиться на CRM» правильно

- **Оперативные факты:** читать свежие данные CRM при запросе.
- **Аналитические выводы:** агрегировать и сохранять только проверенные правила/закономерности, с источником и датой.
- **Контекст клиента:** по законным основаниям и с разграничением доступа, получать только конкретные нужные данные; адреса/телефоны/переписки не отправлять в публичный GitHub.
- **Память:** позже в закрытом Supabase с RLS, минимальными грантами и контролем хранения.
- **Fine-tuning:** не нужен для первичного этапа.
