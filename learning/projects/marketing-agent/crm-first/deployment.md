# Настройка на VPS через n8n Editor

**Важно:** никаких изменений на VPS из этого чата не делали. Импортированные шаблоны не запускаются автоматически. Перед запуском сделай резервную копию n8n, проверь версию и работай в отдельной папке **AI CRM Agent**. Не изменяй текущие n8n интеграции и Supabase.

## Шаг 1: импортируем вызов клиента
1. Скачай [02-get-keycrm-buyer.json](02-get-keycrm-buyer.json) (GitHub → Raw/Download).
2. n8n → новый workflow → Import from File.
3. В HTTP Request `GET buyer from KeyCRM` создай отдельный **Header Auth** credential:
   - header: `Authorization`
   - value: `Bearer <твой_ключ_KeyCRM>`
   - ключ вводится только в защищённом Credential n8n, не в JSON и не в чате.
4. Проверь, что метод именно `GET` и URL `https://openapi.keycrm.app/v1/buyer/{{ $json.buyer_id }}`; узел не может создавать/изменять покупателей.
5. Сохрани subworkflow. Для живых вызовов в некоторых версиях n8n его нужно отдельно **publish** (см. документацию версии). Это не означает открытый публичный webhook.

## Шаг 2: импортируем агента
1. Скачай [01-crm-ai-agent.json](01-crm-ai-agent.json) и импортируй отдельным workflow.
2. В `OpenAI Chat Model` создай/выбери credentials OpenAI API. Подписка ChatGPT — отдельно от биллинга API.
3. В `Get KeyCRM Buyer Tool` поле **Workflow** не заполнено намеренно: выбери `02 - Get KeyCRM Buyer (READ ONLY)` из списка.
4. Убедись, что вход `buyer_id` связан с выражением `$fromAI(..., 'number')`. При несовместимости версии нод настрой маппинг через интерфейс редактора.
5. Не включай публичный чат. Пока не добавляй memory, Telegram, инструменты UPDATE/POST или произвольный SQL.
6. Сохрани; когда будешь готов, проведём только безопасный тест чтения по известному buyer_id.

## Пример работы

Пользователь: «Проверь покупателя KeyCRM с ID 12345»  
Агент вызывает `Get_KeyCRM_Buyer_Readonly(buyer_id=12345)`, получает техническую сводку и рассказывает, что реально подтверждено. **Это только пример, ID не получен из вашей CRM.**

Пользователь: «Перемести его карточку в другой статус»  
Агент не имеет write-инструментов и может только подготовить предложение. Реального изменения не происходит.

## Что возвращает инструмент

- buyer_id
- manager_id, company_id, даты, если присутствуют
- индикаторы, что у записи есть имя/телефон/email
- список названий части полей для последующей настройки

**Не возвращает** адреса, телефоны, email, имена, переписки или комментарии. Исходный HTTP Request всё же получает базовую сущность KeyCRM. Не выставляй execution log в общий доступ и не сохраняй его без необходимости.

## Совместимость

Файлы следуют схеме n8n с AI Agent / Chat Trigger / Execute Sub-workflow Trigger / Call n8n Workflow Tool, но версию твоего экземпляра n8n мы пока не знаем. После импорта проверь, какие ноды интерфейс считает неизвестными. В новых n8n существуют самостоятельные Agents наряду с классическими AI Agent workflow.

## Лимиты

KeyCRM публикует ограничение до **20 запросов в минуту на ключ**. Не запускай массовые переборы ID и не настраивай частые повторные вызовы.
