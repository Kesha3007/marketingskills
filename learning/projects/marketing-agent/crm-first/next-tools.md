# План CRM-инструментов и согласования

## Ступень A — чтение
1. `Get_KeyCRM_Buyer_Readonly(buyer_id)` — реализован как шаблон.
2. `Get_KeyCRM_Card_Readonly(card_id)` → `GET /pipelines/cards/{cardId}`.
3. `Get_KeyCRM_Order_Readonly(order_id)` → `GET /order/{orderId}`.
4. `List_KeyCRM_Orders_Readonly(filters, page)` с лимитом выдачи, ограничениями диапазона, контролем общего API rate limit.
5. `Get_KeyCRM_Pipeline_Statuses_Readonly(pipeline_id)` → `GET /pipelines/{pipelineId}/statuses`.
6. Доступные звонки и комментарии — после проверки контрактов API, ролей доступа, законных оснований обработки; сырые персональные данные не передавать модели без необходимости.

## Ступень B — аналитика
На основании данных CRM строить отчёты с указанием периода, валюты, источника, статусов и недостающих сведений. Нельзя сравнивать агентские догадки с данными CRM как равнозначные факты. Для полного анализа нескольких тысяч записей использовать безопасные агрегирующие процессы, а не массово выдавать API-карточки модели.

## Ступень C — предложения действий (без записи)
Создание карточки, смена статуса, добавление задачи:
- тип операции и точные ID;
- текущие значения из CRM;
- предложенные значения;
- автор запроса и причина;
- ожидаемая версия записи/контроль изменения между прочтением и записью;
- статус `pending_approval`.

## Ступень D — подтверждения и запись
Защищённая отдельная approval-служба: однократное подтверждение пользователем с проверкой роли и срока действия, allowlist разрешённых операций, отдельный исполнитель с минимальными правами, idempotency key, аудит и повторная сверка результата. Само сообщение «подтверждаю» в публичном чате не может быть единственным механизмом авторизации.
