# Архитектура нашего агента — проект v0

## Разница компонентов
**Skills**: методы работы (Marketing Skills).
**Модель**: OpenAI API (рассуждает над доступным контекстом).
**Оркестратор**: n8n (триггеры, интеграции, маршрутизация, ограничения доступа).
**Инструменты**: строго определённые API-функции для чтения данных, позже — разрешённых действий.
**Контекст**: продуктовые инструкции из `.agents/product-marketing.md` и внутренних проверенных материалов.
**Хранилище**: Supabase — возможно для структурированной истории, аналитики и состояния; на этапе v0 не требуется.
**GitHub**: версионирование шаблонов, инструкции и исходники; НЕ хранилище секретов и клиентских данных.

## Схема целевого потока

```text
Ты (чат в n8n / другой защищённый интерфейс)
   |
   v
n8n (триггер + права + этапы выполнения)
   |---------------------> OpenAI API (модель)
   |                           |
   |                           v
   |                     Инструкции/Skills
   |
   +--> безопасные read-only инструменты
   |        |- KeyCRM: список заказов / статусы по ограниченному запросу
   |        |- GA4: агрегированные данные
   |        |- Google Ads/Meta: расходы и результаты
   |        |- Ringostat: обезличенные/агрегированные события
   |        |- Supabase: отдельное закрытое хранилище (позже)
   |
   +--> результат: факты, гипотезы, пробелы, рекомендации
   |
   +--> черновики действий -> отдельное подтверждение -> API write с журналом
```

Интеграции на схеме — **план**, а не утверждение о подключении.

## Рынки
Два набора контекста/прав: Prague / Kyiv Oblast. Запрос должен явно содержать рынок либо агент должен уточнить; не смешивать валюты, условия доставки, рекламу и клиентские данные.

## Режимы развёртывания
1. **n8n Cloud:** не требуется свой VPS для оркестратора. Отдельно оплачиваются соответствующие сервисы/API.
2. **Существующий n8n на VPS:** можно использовать его, если есть права, достаточные ресурсы и надёжная защита (TLS, аутентификация, backup).
3. **Свой Python-сервис:** когда возможностей workflow мало, через OpenAI Agents SDK / Responses API. Требует развертывания приложения и эксплуатации.
4. **OpenAI управляемый runtime:** Agents API — альтернативный путь без собственного агента-оркестратора, но инструменты и разрешения всё равно надо организовать.

## Безопасность данных
- Никогда не отправлять в репозиторий ключи, номера телефонов, email клиентов, записи звонков и секреты.
- Начать с обезличенной сводки; доступ к карточкам клиентов — только если реально нужен, с ограничениями и законным основанием обработки.
- Выделить права чтения отдельно от создания/изменения.
- Изменения бюджетов, кампаний, клиентов, задач — только через ограниченные функции и подтверждение.
- Supabase (позже): RLS в публично доступных схемах, минимум GRANT, сервисные ключи только на сервере. Доступность через Data API и политики RLS — разные ограничения.
- Параллельные задачи и повторные вызовы не должны приводить к дублированию действий.

## MVP
Одно агентное окно с бизнес-инструкциями и тестовыми обезличенными данными. Успех v0 = верные ответы на контрольные вопросы и честное указание отсутствующих данных. Не путать MVP с настоящим подключением к рекламным аккаунтам.
